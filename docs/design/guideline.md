# 공모 가이드라인 (v0.20에서 정리한 논점)

> CLAUDE.md 5-2 에서 옮김(2026-09-11). 문장은 고치지 않았다.


사용자가 원한 것: 가이드라인을 올리면 ① 분석하고 ② 목차·집필카드를 만들고
③ **각 항목에 필요한 자료를 정리**해 준다(지역현황 → 인구통계·면적·기후처럼 여러 부서에
흩어진 것들).

## 이것은 새 파이프라인이 아니다

`services/templates.py` 의 **정적 틀 옆에 놓인 '동적으로 만들어지는 틀'** 이다.
분석 결과의 `tree` 는 `DOC_TEMPLATES` 의 `nodes` 와 **모양이 같다**(`{title, children, card}`).
그래서 프런트의 `buildFromTemplate` → `PUT /outline` 경로를 그대로 타고,
`replace-preview` 로 세워 둔 파괴 방지 장치도 함께 물려받는다.
`doc_type` 은 건드리지 않으므로 초고 문체(`family_of`)도 흔들리지 않는다.
**목차를 백엔드에서 심지 말 것** — 두 경로가 생기면 확인 문구가 어긋난다.

## AI 가 지어내지 않는 이유 (원칙 2)

**필요 자료는 이미 가이드라인 본문에 적혀 있다.** 상상할 것이 아니라 읽어 낼 것이다.
그래서 자료 하나하나에 출처(`src_block`/`src_page`/`source`)가 붙고 화면에 표시된다
— 담당자가 "이거 진짜 필요한 자료 맞나"를 원문에서 확인할 수 있어야 한다.

역할 분담(이 경계를 흐리지 말 것):

| 하는 일 | 누가 |
|---|---|
| 텍스트 추출, 계층 인식, 지시문·각주·표 머리글 뽑기 | **규칙**(guideline.py) |
| 후보가 '자료'인지 '용어 설명'인지 판정 | LLM |
| 뭉뚱그린 말을 부서에 보낼 문구로 다듬기 | LLM |
| 소관 부서 추정 | LLM(있는 부서 중에서만) + 과거 `data_requests` 유사도 |
| 배점 ↔ 목차 짝짓기 | 규칙(`hwpx_form.similarity` 재사용) |

**문서를 통째로 LLM 에 넣지 않는다.** 규칙이 뼈대를 다 뽑아 두므로 항목 12개씩 끊어
보낸다(`skills/guideline_analysis.py` 의 `CHUNK`). 44쪽 43,000자를 매번 밀어 넣으면
비싸고 자주 실패한다. **키가 없어도 목차와 표 기반 자료 목록은 나온다** — 이 폴백을
없애지 말 것(담당자 진술 폴백과 같은 이유).

## 실물에서 배운 것 (2026-08-29, 공고 .hwpx / 가이드라인 .pdf / 서식 .hwp)

- **한글은 문서 한 쪽을 통째로 1칸짜리 표에 넣기도 한다.** 어느 시·도 공고문은 본문
  32문단이 전부 한 칸 안에 있었다. `_hwpx_cell_text()` 가 칸 안 문단을 공백으로 이으면
  문서 전체가 한 덩어리가 되어 목차가 하나도 안 나온다. **줄바꿈으로 남기고**
  `table_lines()` 가 다시 글줄로 편다.
  다만 그 줄바꿈이 **이름으로 쓰이는 자리**(배점표 지표명·표 머리글)로 새면 `성과
도출`
  처럼 깨지고 유사도 짝짓기도 흐트러진다 → 그 자리는 `guideline.flat()` 로 눕힌다.
- **한글 서식은 제목과 `※` 안내를 1칸짜리 표(글상자)로 그린다.** 표로 다루면 목차도
  집필카드도 통째로 사라진다. `guideline.table_lines()` 가 칸이 한 종류뿐인 표를
  글줄로 편다. 이 함수를 지우면 공고문에서 목차가 하나도 안 나온다.
- **빈 표가 곧 자료 요구다.** `읍·면 │ 전체 개소수 │ 가맹점수(가맹율)` 짜리 빈 표는
  "그 자료를 구해 오라"는 뜻이고, 단위·구분까지 들어 있어 문장보다 정확하다.
  다만 **머리글만으로는 무엇의 표인지 모른다**(실물 #7, 2026-11-25: `읍·면 · 명칭 · 이용현황 · 소재지 · 비 고` —
  부서가 무엇을 채우라는지 알 수 없었다). 표 바로 앞 글줄(3블록 안, `(단위 : …)` 줄은 건너뜀)을 표 이름으로 앞에 붙인다.
  `붙임 N · 제목` 띠는 스스로 이름이라 앞 줄을 달지 않고(앞 줄은 대개 앞 서식의 '…장관 귀하'다),
  칸마다 `직인`·`서명` 인 표(서명란)는 자료 요구가 아니라 뺀다.
- **문서마다 표시가 다르다.** 가이드라인 PDF 는 `제N절 / N. / ①` + `주요내용`·`방법`·`*`,
  공고 HWPX 는 `Ⅰ. / 1. / 가.` + `※`. 그래서 계층 표지를 **후보군**(`MARKERS`)으로 두고
  그 문서에 실제로 나온 것만 골라 고정 우선순위로 깊이를 매긴다.
  **규칙 하나로 고정하면 다음 문서에서 반드시 깨진다.**
- **배점표는 표이고 병합셀이 있다.** 문단으로 읽으면 '배점 20'이 어느 지표 건지 사라진다.
  `doc_read._hwpx_grid()` 가 `cellAddr`/`cellSpan` 으로 격자를 펴서 **행 하나가 스스로
  완결**되게 한다. 짝짓기에는 가장 구체적인 마디(`score_label`)와 세부기준 앞머리를 쓴다
  — 펼친 탓에 `공통 배점 (80) · 소멸 위험도 (10)` 처럼 뭉쳐 나오면 유사도가 희석된다.
- **짝이 안 맞는 쪽이 더 중요하다.** 대응 목차가 없는 심사항목 = 빠뜨린 항목(감점·반려의
  실제 원인), 배점 없는 목차 = 분량을 줄여도 되는 항목. 둘 다 화면에 내보인다.
- **접수 기간은 뒤쪽 날짜에 연도를 생략한다**(`‘25. 9. 29. ~ 10. 13.`). 마감일이 바로 그
  생략된 쪽이므로 `dates_in()` 이 앞 연도를 물려받는다.

## 읽을 범위는 사람이 고른다

공고문은 사업 설명·평가 기준·서식이 뒤섞여 있다. 자동 추정(`guess_range`)은 **기본값일
뿐**이고 화면에서 고칠 수 있다. 조용히 틀린 구간을 읽고도 그럴듯한 결과를 내놓는 것이
가장 위험하다. 이 화면을 없애고 완전 자동으로 만들지 말 것.
