## 2. 설치·실행 절차

**권장 — 설치 없이 실행(포터블 꾸러미)**

1. 공공GitLab 프로젝트의 **릴리스(Releases)** 에서 `행정기획워크벤치_포터블.zip` 을 내려받습니다.
2. 압축을 풉니다. `행정기획워크벤치_포터블` 폴더가 생깁니다.
3. 폴더 안의 **`실행.bat`** 을 더블클릭합니다.
4. 검은 창(서버)이 뜨고 잠시 뒤 브라우저가 `http://127.0.0.1:8000` 으로 열립니다.
   열리지 않으면 주소창에 직접 입력합니다. **검은 창은 사용하는 동안 닫지 않습니다.**
5. 끌 때는 검은 창을 닫습니다.

【화면 캡처: 첫 화면(대시보드)】

**다른 방법 — 파이썬·Node.js 가 있는 PC 에서 소스로 실행**

```
1_SETUP.bat   (최초 1회, 인터넷 필요 — 파이썬 가상환경 + 화면 부품 설치)
2_START.bat   (실행 — 브라우저가 http://localhost:5173 으로 열립니다)
```
필요: Python 3.11 이상, Node.js 18 이상. 자세한 것은 저장소의 `README.md`.

## 3. LLM 연결 설정

**AI 키가 없어도 프로그램은 정상으로 뜨고**, AI 가 아닌 기능(자료 읽기·목차·근거 확정·공고 규칙 분석·
내보내기·진행상황·**주민 설문 설계**)은 모두 동작합니다. AI 기능은 "키가 없습니다"라고 **분명히** 알리고 멈춥니다.

**연결하는 곳:** 화면 맨 위 **'설정' → 'AI 연결'**. 저장하면 바로 반영됩니다(다시 켤 필요 없음).

1. **API 키** 칸에 쓰려는 회사의 키를 붙여 넣고 저장합니다. 키는 이 PC 의 DB 파일에만 저장됩니다.
2. **등급별 모델**: 일의 무게에 따라 세 등급으로 나눠 씁니다. 등급마다 회사와 모델을 따로 고를 수 있습니다.

   | 등급 | 하는 일 |
   |---|---|
   | 빠름 | 담당자 진술 쪼개기 |
   | 기본 | 자료 분석 · 공모 가이드라인 판정 · 보고전 초고 · 구조 검토 |
   | 정밀 | 계획서 초고 · 사실확인 검토 · 기술 검토 · 비평 |

   모델 칸을 비워 두면 추천값을 씁니다. **'목록'** 을 누르면 그 회사가 지금 제공하는 모델을 불러와 고를 수 있습니다.
   빠름·정밀을 '기본과 같게'로 두면 모델 하나로 모든 일을 합니다.
3. **'시험'** 을 눌러 실제로 한 번 물어봅니다. 실패하면 키가 틀린 것인지, 모델 이름이 없는 것인지, 망이 막힌 것인지를 구분해 알려 줍니다.

**모델 교체 — 특정 모델에 종속되지 않는 구조**
- 지원: **OpenAI · Claude · Gemini · 호환 서버** 네 가지. 회사·모델은 위 화면에서 언제든 바꿉니다.
- AI 를 부르는 코드는 "무슨 일인지"만 말하고, 어느 회사·모델을 쓸지는 설정 한 곳에서 정합니다.
- 결과(초고·분석)에는 **실제로 쓴 회사·모델 이름이 함께 기록**됩니다. 실패해도 다른 모델로 몰래 넘기지 않습니다.

**행정안전부 AI 공통기반 지원 모델(엑사원·솔라·젬마·라마·GPT-OSS 등) 연결 — '호환 서버'**
- 공통기반 모델은 대개 OpenAI 호환 주소(`/v1/chat/completions`)를 내줍니다. 'AI 연결'의 **호환 서버** 칸에
  - **OpenAI 호환 주소**: 예) `http://서버주소:포트/v1`
  - **API 키**: 인증이 없는 서버면 비워 둡니다
  - 등급 칸에서 회사를 '호환 서버'로 고르고, 모델 이름은 **'목록'** 으로 불러와 고릅니다(추천값이 없습니다 — 기관마다 올린 모델이 다르기 때문).
- 【채울 것: 공통기반 지원 모델 구동 시연 — 사용한 모델 이름·서버 방식(예: Ollama 로 띄운 Gemma/EXAONE), 주요 기능(공고 판정·초고·검토)이
  정상 동작한 결과. 집 PC 에서 확인 후 작성 — `docs/challenge-2026.md` 3번】

**관리자가 미리 넣어 반입하는 방법(선택):** 꾸러미의 `backend\.env` 에 같은 항목(`LLM_PROVIDER`, `OPENAI_API_KEY`,
`COMPAT_BASE_URL` 등)을 적을 수 있습니다. 화면에서 넣은 값이 `.env` 보다 앞서며, 화면에 어느 쪽 값인지 표시됩니다.

## 4. 모의데이터 안내

저장소의 `모의데이터/` 폴더(또는 함께 제출하는 압축)에 가상의 **'가온군 스마트 경로당 조성 공모사업'** 한 건이 있습니다.
지역·기관·수치는 모두 지어낸 것이고 개인정보가 없습니다. 파일끼리 수치가 서로 맞습니다.

| 파일 | 용도 | 투입 방법 |
|---|---|---|
| `01_공고_…hwpx` | 공모 공고문(한글) | 목차 편집 → **가이드라인에서 만들기** |
| `06_정정공고_…hwpx` | 정정 공고(배점 2개 조정 + 마감 연장) | 같은 창에서 두 번째 파일로 올려 비교 |
| `02_…노인인구 현황(주민복지과 회신).xlsx` | 부서 엑셀 회신(병합 머리글·날짜) | 자료·근거 → **파일에서 등록** |
| `03_…경로당 운영 현황(행정시스템 내려받기).xls` | 행정시스템 내려받기 파일(실제로는 HTML 표) | 자료·근거 → **파일에서 등록** |
| `04_…실태조사 결과보고(요약).docx` | 워드 보고서(문단 + 표) | 자료·근거 → **파일에서 등록** |
| `05_담당자 진술(붙여넣기용).txt` | 문서로는 없는 담당자의 사실 | 자료·근거 → 담당자 진술 칸에 붙여 넣기 |

주민 설문(흐름 4)은 따로 넣을 파일이 없습니다. 위 공고로 심은 목차와 03 의 **등록 회원 6,100명**(대상 인구)을 씁니다.

자세한 순서는 `모의데이터/안내.txt`.

## 5. 기능 사용 순서 (핵심 흐름 4개)

**흐름 1. 공고문 → 목차·배점 (AI 키 없이도 됩니다)**
1. 맨 위 **'+ 새 업무'** → 업무 이름 입력.
2. **목차 편집** → **'가이드라인에서 만들기'** → `01_공고` 를 올리고 분석합니다.
3. 결과: 목차(장 5개와 그 아래 항목 합쳐 12개)와 항목별 작성 안내, 빈 표에서 읽은 **필요한 자료**, **심사 배점 ↔ 목차 짝**,
   접수 마감일 후보. 특히 **'지방비 확보(10점)'는 대응하는 목차가 없다**고 경고합니다 — 계획서에서 빠뜨리기 쉬운 자리입니다.
4. **채택**해야 목차가 심어집니다(AI·규칙은 제안, 확정은 사람).
5. (선택) `06_정정공고` 를 올려 비교 → 마감일 변경 1건, 배점 변경 2건. 자동으로 고치지 않고 알려만 줍니다.

【화면 캡처: 배점 ↔ 목차 짝과 '대응 목차 없음' 경고】

**흐름 2. 자료 → 근거 확정**
1. **자료·근거** 탭의 **'파일에서 등록 (한글·엑셀·워드·PDF)'** 으로 02·03·04 파일을 올립니다. 표는 칸 그대로 읽고 원본도 보관합니다.
2. 자료마다 **'AI 분석'** → 제안을 보고 **'분석 확정'** 을 눌러야 비로소 **근거**가 됩니다. *확정 전에는 근거가 아닙니다.*
3. **담당자 진술** 칸에 05 의 문단을 붙여 넣고 쪼갠 뒤 채택할 문장만 고릅니다. 채택한 진술은 끝까지 **[진술]** 로 표시됩니다.
4. 근거를 목차 항목에 연결합니다. 자료 내용을 고치면 그 자료를 쓴 모든 근거에 **'원본이 바뀌었다'** 신호가 뜹니다.

**흐름 3. 초고 → 검토 → 최종본**
1. **초고 작성** 탭: 항목을 골라 초고를 제안받습니다. 기본은 **'엄격 — 확정 근거 안에서만'** 이고, 근거가 없는 자리는 [확인 필요]로 남습니다
   ('유연'은 연결문장을 허용하되 추측을 표시). 본문 채택은 사람이 합니다.
2. **검토** 탭: 사실확인·기술·구조·비평 네 검토자가 **의견만** 냅니다(본문을 직접 고치지 않음).
   예) 진술의 "군비 매칭은 아직 확정되지 않았다"와 어긋나게 쓴 문장을 사실확인 검토가 짚어 내는지 볼 수 있습니다.
3. 부족한 자료는 검토 의견의 **'자료요청으로'** 를 눌러 넘기고, 부서별 요청서(.xlsx)를 만듭니다.
4. **최종본** 탭: 점검 후 근거 부록이 붙은 **.docx** 로 내보냅니다.

【화면 캡처: 검토 의견 목록 / 최종본 점검】

**흐름 4. 주민 설문 설계 — 응답을 받기 전에 (AI 키 없이도 됩니다)**

설문을 다 받은 뒤 "이걸로 무엇을 말할 수 있나"를 찾으면 늦습니다. 그래서 **계획서의 주장 → 무엇으로 받치나 → 문항 → 분석 계획**을
수집 전에 정합니다. 설계한 설문지가 곧 분석 틀이 됩니다.
1. **설문** 탭 → **'새 설문'**. 대상 "관내 경로당 등록 회원", 대상 인구 **6,100**, 오차범위 ±5%p → **목표 응답 362명**을 계산합니다.
2. **① 근거 지도**: 목차 항목마다 주장을 적고 무엇으로 받칠지 고릅니다.
   예) 'Ⅰ-1 사업 배경 및 필요성'의 "고령화가 심하다"는 **통계** → **'자료요청으로'** 를 누르면 자료요청 대장에 들어갑니다.
   'Ⅲ-1 추진 내용'의 "주민이 원하는 프로그램이 있다"는 **설문** → 그 자리에서 문항을 만듭니다.
3. **② 문항 설계**: 문항마다 **받치는 주장**과 **분석 계획**(예: 원하는 프로그램 × 연령대)을 정합니다.
   연령대·읍면은 **응답자 특성** 문항으로 두고, 보기는 통계 구분(읍·면 7개 이름 그대로)과 같게 만듭니다.
   "경로당을 이용하십니까"에 '아니오'면 이유 문항으로 건너뛰는 **분기**도 정합니다.
4. **③ 점검**(오른쪽 칸): 문항이 없는 주장, 주장이 없는 문항, 앞으로 돌아가는 분기, 개인정보 문항,
   고령층 대상인데 온라인 폼뿐인 방식 등을 **의견으로만** 짚습니다(문항을 고치지 않음). 누르면 그 문항으로 갑니다.
   예) 방식을 '온라인 폼'으로 두면 현장에서 태블릿으로 같은 폼에 대신 입력하는 방식을 권합니다.
5. **④ 폼으로 옮기기**: 구글폼에 그대로 옮겨 적는 표를 **.xlsx** 로 받습니다(문항표 · 폼 설정 점검표 · 근거 지도 · 조사 개요).
   폼의 분기는 섹션 단위로 움직이므로 섹션을 미리 나눠 둡니다.

## 6. 알려진 제약 사항

- **단일 사용자·로컬 도구**입니다. 동시 편집·권한 관리는 없습니다. 팀 분업은 '진행상황 보고 파일'을 주고받아 **보이게** 하는 방식입니다(서버를 두지 않기 위해).
- **AI 기능에는 인터넷과 키**(또는 기관 호환 서버)가 필요합니다. 응답 시간·품질은 고른 모델에 따릅니다.
- 호환 서버(공통기반 모델)는 OpenAI 호환 규약을 따르는 서버를 전제로 합니다. 스트리밍·도구 호출은 쓰지 않습니다. 【3번 시연 결과에 따라 고칠 것】
- 구형 **.hwp** 는 글자는 읽지만 표 구조는 잃을 수 있습니다 → 한글에서 .hwpx 로 저장해 올리면 표까지 읽습니다(화면에서도 그렇게 안내).
  스캔한 PDF(그림)는 글자를 읽지 못합니다.
- **주민 설문은 설계(①~④)까지**입니다. 폼에서 받은 응답 파일을 올려 정리·집계하고 근거로 확정하는 단계(⑤~⑧)는

## 7. 개발 경위 요약 (1쪽 이내)

**문제 인식**

군청 기획 담당자는 공모사업 계획서·군정 보고서를 짧은 기한 안에 써야 합니다. 그 과정에서 반복해서 부딪힌 문제는 세 가지였습니다.
- **근거가 흩어진다.** 부서 회신(엑셀), 행정시스템 내려받기, 한글 공고문, 담당자의 머릿속 사실이 제각각이라, 계획서의 숫자가 어디서 왔는지 나중에 확인하기 어렵습니다.
- **생성형 AI 초안은 빠르지만 믿기 어렵다.** 그럴듯한 문장이 근거 없이 섞이고, 사람이 어디를 고쳐야 하는지 알 수 없습니다.
- **공고문을 읽는 데 시간이 든다.** 목차·작성 안내·배점·필요한 자료를 읽어 내고, 배점 항목을 계획서에서 빠뜨리지 않았는지 맞춰 보는 일이 매번 반복됩니다.
- **설문이 계획서를 받치지 못한다.** 설문을 받은 뒤에야 쓸 말을 찾다 보니, 빠진 문항은 되살릴 수 없고 결과를 주장에 끼워 맞추게 됩니다.

**접근 방식 — "AI 는 제안하고, 사람이 확정한다"**
- **근거로 통제한다.** 자료는 분석 → **사람의 확정**을 거쳐야 근거가 되고, 초고는 확정한 근거 안에서만 씁니다. 자료가 바뀌면 그 자료를 쓴 모든 곳에 신호가 뜹니다.
- **AI 의 역할을 나눈다.** 공고문의 구조(목차·배점·빈 표)는 **규칙**으로 읽고, AI 는 판정과 문구 다듬기만 합니다 — 그래서 키가 없어도 목차는 나옵니다. 검토자는 **의견만** 내고 본문을 고치지 않습니다.
- **설문도 근거로 설계한다.** 계획서의 주장마다 통계로 받칠지 설문으로 받칠지 먼저 정하고, 문항마다 받치는 주장과 분석 계획을 수집 전에 붙입니다.
- **행정 실무의 감각을 따른다.** 결재란 같은 단계 띠, 기안 → 검토 → 확정의 흐름을 화면에 그대로 옮겼습니다.
- **행정망에서 돌아가게.** 설치·서버 없이 폴더 하나로 실행하고, 자료는 PC 안의 파일 하나에만 둡니다. 특정 AI 회사에 묶이지 않도록 회사·모델을 설정에서 바꾸게 했고, 공통기반 모델용 '호환 서버' 칸을 따로 두었습니다.

**개발 방식**

【채울 것: 개발자·기간·도구 — 예) 2026년 ○월부터 담당자가 생성형 AI 코딩 도구와 함께 직접 개발. 2026-08-28 v0.17, 현재 v0.29】
기능 목록을 위에서부터 해치우기보다 **실제 업무 한 건을 처음부터 끝까지** 해 보고 손이 멈추는 자리를 고쳤습니다.
담당자 진술, 보고전 뽑기, 공고문 분석이 모두 그렇게 생겼습니다. 공공GitLab 보안 스캔(Gitleaks·Semgrep·OSV-Scanner·Trivy·Syft)에서
