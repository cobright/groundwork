# 버전 흐름 (무엇을 왜 했는가)

> CLAUDE.md 에서 옮겨 온 이력(2026-09-11). 결정의 **이유**는 `docs/design/*`·`docs/lessons.md` 에 있다.
> 원래는 v0.25→v0.22 가 거꾸로 적혀 있어 버전 순으로 다시 늘어놓았다. 문장은 고치지 않았다.

## 버전별

v0.1~0.7 기초: 목차 → 자료+AI분석+근거표 → 자료수정 → AI초고 → 사실확인검토 →
검토자완성(기술·구조·비평) → 최종본(.docx).
v0.8~0.9 공통자료실: 부서 폴더 + 단순 참조(스냅샷 아님) + 승격(업무자료→공통).
v0.10~0.11 부서 자료요청서: 수집(초고 [확인 필요] + 검토 필요조치, 중복방지) +
부서배정 + 상태관리 + 발송/마감/회신자료 등록 + xlsx(부서별 시트).
v0.12 대시보드: 업무 가로지르는 집계 + 업무 마감일(부분수정으로 필드보존).
v0.13 대시보드 홈 + 외형('상황실' 톤, 결재란 단계 띠).
v0.14 진행상황 보고 ①: 보고 팝업(자동사실 읽기전용 + 사람 한마디) + 내 이름 설정 +
보고파일(JSON: 기계용 구조 + 사람용 human_summary).
v0.15 받은 보고 ②: 폴더의 보고파일을 읽어 (보고자·업무)별 최신만, 업무별/팀원별 보기.
v0.16 폴더 선택창(pick-folder).
v0.17 포터블 배포 준비(설치 없이 행정망 실행).
v0.18 검토 반영: 근거 번호 단일화(E-번호), 근거 변경신호 '확인함' 분리,
  포터블 꾸러미에서 .env 제외, 목차/업무명 저장 타이머 분리, 설치 스크립트 자가검증,
  목차 번호 계산 통합(services/numbering.py), 지워진 목차의 유령 본문 정리(진행률 오계산 수정).
v0.18 보관함(캐비넷): 삭제 앞에 '보관' 단계. 지워야 할지 모르겠으나 지금 관리 대상이 아닌
  업무를 넣어두는 곳. 상황판 하단 접이식 + 되살리기, 삭제는 보관함 안에서 업무명 재입력으로만.

     테스트 15개(미들웨어를 빼면 공격 8개가 실패하는 것을 확인) + 실제 Chrome 에서 127.0.0.2 출처 페이지의 업로드·읽기가 막히는 것을 확인.
  근거 점검기(`services/evidence_check.py`): 기능 분석에서 "근거 통제가 지시문 수준"이라고 짚은 것을 메웠다.
     ① 초고에 미확정 근거를 넘기지 않는다(예전엔 [미확정] 표시만 달아 넘겼다 — 원칙 2 와 어긋났다).
     ② 문장마다 숫자·(근거: E-번호)를 자료 **원문**과 규칙으로 대조 — 없는 번호(중대)·원문에 없는 숫자·미확정 인용·
        바뀐 원본 인용·근거 없는 수치 문장(중요). 초고 화면(제안·본문)과 최종본 점검에 붙였다.
     AI 요약은 대조 원문에 넣지 않는다(테스트가 지킨다). 숫자를 글자 그대로 찾으므로 단위 환산·계산값도 짚는다 — '확인하라'는 의견.
     테스트 12개 — 미확정을 다시 넘기게 하거나 요약을 원문으로 치게 하면 각각 실패하는 것을 확인.
  출구 테스트: `.docx` 내보내기(8%→92%)·한글 양식 채우기(13%→93%). 실제 기관 양식은 공개할 수 없어 `tests/hwpx_sample.py` 가
     가상 양식을 만든다(줄바꿈 캐시·쪽번호 재시작·옛 목차·[붙 임] 꼬리 같은 함정 포함). 캐시를 안 지우거나 묶는 순서를 바꾸면 실패함을 확인.
  AI 품질 시험 묶음(`evals/ai_eval.py`): 모의데이터로 실제 AI 를 돌려 규칙으로 채점 — C1 자료분석 지어낸 숫자, C2 초고 근거 밖 숫자,
     C3 근거 없을 때 [확인 필요], C4 진술 함정(미확정 군비를 '확보'로 단정), C5 사실확인이 함정을 잡나, C6 가이드라인 AI 정리.
     채점 자체는 가짜 AI 둘(잘하는/환각하는)로 6/6·0/6 이 나오는지 테스트한다. 전체 테스트 범위 42%→54%.
  첫 실제 AI 시험(OpenAI gpt-5.6-luna·sol): 6/6 통과. 출력을 읽어 보니 두 문제 —
     ① 점검기 헛경보: "…감소하였다. 반면 …증가하였다. (근거: E-001)" 의 첫 문장을 '근거 없는 수치'로 짚었다 → 줄 끝 번호를 앞 문장에 물려준다.
     ② 초고가 '### 1. 노인 인구 현황' 처럼 목차 제목을 마크다운으로 되풀이 → 지시문에 금지 + `tidy_markup()` 이 표시만 걷는다 + C7(지시문 준수) 추가.
     C5 는 군비 진술의 근거 번호를 달도록 고쳤다. 다시 돌려 7/7, 정리기가 걷어 낸 곳 0, C2 점검 의견 0.
  **실제 업무 한 건(#6 농어촌기본소득)을 처음으로 최종본까지** 써 봤다(근거 1건·본문 1개의 가장 짧은 길).
     그 전엔 업무 9건 모두 확정 본문 0 — 쓰인 건 공고→목차→자료요청까지였다(뒤 절반은 모의데이터로만 검증돼 있었다).
     잘 된 것: AI 분석이 엉뚱한 회신(인구지표 요청 → 기금 건의안)을 "요청한 ○○은 이 자료에 없습니다"로 짚었고,
       초고가 지어내지 않고 [확인 필요]로 남겼다. 근거 점검기 헛경보 0(숫자가 적어 시험으론 약함).
     드러난 것 셋 → 고침: ① 그 회신이 그대로 확정돼 부록에 요청 이름 '읍·면별 … ✔'로 찍힘(자료명이 요청 문구로 자동으로 붙어서)
       → 확정 전 경고·확인 + 재요청 되돌리기 + 최종본 점검. ② 근거 주장이 '새 주장' 그대로 부록에 → 빈칸으로, 점검이 짚음.

     아직 모르는 것: '자료마다 분석→확정→근거→목차 연결 네 단계가 무거워 멈췄다'는 가설 — 이번 길이 짧아 확인 못 함.
