# 하드-런 교훈 — 사고 경위

> CLAUDE.md 6장에서 옮김(2026-09-11). CLAUDE.md 6장에는 **규칙 한 줄씩**만 남기고,
> 왜 그런 규칙이 생겼는지는 여기 **같은 소제목** 아래에 둔다. 문장은 고치지 않고 주제별로 묶기만 했다.
> 새 교훈을 더할 때도 같은 방식: 경위는 여기에, 규칙 한 줄은 CLAUDE.md 6장에.

## 배포·실행 환경

- **`.bat` 파일 내용은 순수 ASCII + CRLF + BOM 없음.** 한글을 .bat *내용*에 넣으면
  cmd가 깨진다(한글 *파일명*은 괜찮다). 한글 안내는 `.txt`(UTF-8)에 둔다.
  PowerShell `.ps1`에 한글을 넣을 땐 UTF-8 **BOM** 저장.
- **`.bat` 의 자가검증 import 목록은 손으로 관리된다**: `1_SETUP.bat` 의
  `import fastapi, pydantic, ... , pypdf` 는 `requirements.txt` 를 읽지 않는다.
  패키지를 추가하면 **두 곳 모두** 고쳐야 한다(포터블 스크립트는 requirements 를 읽으므로 자동).
- **임베디드 파이썬엔 tkinter가 없다** → 폴더 선택창은 tkinter 실패 시 윈도우
  PowerShell 폴더 대화상자로 폴백(inbox.py). 둘 다 안 되면 직접 입력.
- **포터블 조립은 윈도우에서** 실행된다(임베디드 파이썬 + win_amd64 휠). 리눅스
  개발환경에서 최종 꾸러미를 만들 수 없다.
- **`_hwp_read_prototype.py` 는 이제 `services/doc_read.py` 로 승격됐다**: 시제품 파일은
  참고용으로 남아 있지만 import 되지 않는다. .hwp 관련을 고칠 때는 `doc_read.py` 쪽이다.
  제어문자 폭(EXT/INL, 특히 탭=9)은 그대로 옮겼다 — 줄이지 말 것.

## 한 곳에서만 만든다

- **근거 번호(E-번호)는 한 곳에서만 만든다**: `services/numbering.py`. 업무 전체를
  id 순으로 매긴 통번호이며 근거표·초고 프롬프트·사실확인 검토·최종본 부록이
  모두 이 번호를 쓴다. 예전에 근거표는 전체 순번, 초고는 목차별 순번을 써서
  본문의 `(근거: E-003)`이 근거표의 다른 항목을 가리키는 사고가 있었다.
- **목차에 연결된 근거를 모으는 함수는 `services/evidence.py`의 `linked_evidence()` 하나다**:
  예전엔 `outline.py`(초고)와 `review.py`(검토)에 똑같은 `_linked_evidence`가 복제돼 있었다.
  담당자 진술이 생기면서 한쪽만 고치면 **초고와 검토가 서로 다른 근거를 보게 되므로** 합쳤다.
  근거의 성격을 새로 만들 때는 반드시 이 함수와 `evidence_mark()`를 함께 본다.
- **목차 틀은 `services/templates.py` 한 곳에만 있다**: 예전엔 프런트 `api.js`의 `TEMPLATES`
  상수였다. `doc_type`이 초고 문체까지 가르게 된 순간(v0.19) 틀과 문체가 두 곳에 나뉘면
  유형이 늘 때마다 반드시 어긋나므로 백엔드로 합쳤다. 프런트는 `GET /api/templates`로 받아 쓴다.
  같은 이유로 `outlineModel.js`의 `buildNodes`를 지우고 `buildFromTemplate` 하나만 남겼다.
- **파괴적 확인 문구는 함수 하나로 모은다**: 가이드라인 채택도 목차를 통째로 갈아끼운다.
  틀 심기(`generate("replace")`)와 문구가 갈라지면 한쪽만 고쳐 v0.19 사고가 되풀이되므로
  `App.jsx` 의 `confirmReplace(what)` 하나로 합쳤다. **새로 목차를 심는 경로를 만들면
  반드시 이 함수를 거칠 것.**
- **문서 형식별 파서를 화면 가까이 두지 말 것**: `doc_read.py` 가 pdf/hwpx/hwp/xlsx/docx 를
  **하나의 중간형식**(문단·표)으로 통일하므로, 구조를 읽는 규칙은 한 벌이면 된다.
  자료 등록·회신 등록의 파일 업로드도 이 함수를 쓴다(형식 분기를 새로 만들지 말 것).
- **파일 입구가 늘어도 엔진은 하나다**: 공통자료실에 파일 등록을 붙일 때 `library.py` 가
  형식 분기를 새로 만들지 않고 `services/attachments.py` 를 그대로 불렀다. 입구는 이제 셋이다
  (업무 자료·회신·공통자료). **공통자료는 원본 보관이 더 중요하다** — 한 사람이 읽어 옮긴
  글자를 여러 업무가 근거로 쓰게 되기 때문이고, 본문을 한 글자만 고쳐도 참조하는 업무
  전체에 `source_changed` 가 간다(그래서 파일 자료의 본문은 접어서 읽기만 한다).
- **같은 파일을 두 번 올리게 하지 말 것**: 공모에는 공고·가이드라인과 함께 제출 서식이 온다.
  원본이 이미 `guidelines` 에 있으므로 `POST /guidelines/{gid}/to-form` 이 옮긴다.
  검사·저장은 `services/formstore.py` 한 곳 — 문이 둘(직접 올리기·가이드라인에서 넘기기)이라
  각자 검사하면 '어떤 양식은 되고 어떤 양식은 안 되는' 상태가 된다.
  가이드라인 쪽 원본은 **지우지 않는다**(정정 공고 대비가 그쪽의 일이다).
- **중복 방지 키는 두 문이 같은 것을 써야 한다**: 검토의견을 그 자리에서 자료요청으로 잇는
  문(`/review/{oid}/to-request`)이 `origin_ref` 를 자동 수집과 같은 `op:{id}` 로 쓴다.
  다르게 지었다면 여기서 만든 요청이 <자동 수집>에서 한 번 더 만들어졌을 것이다.
  이 문은 **필요조치(needs)가 빈 의견도** 요청으로 만든다 — 자동 수집이 못 하던 일이고,
  '자료요청 화면에서 다시 수집해야 한다'는 불편의 절반은 사실 그것이었다.
- **숫자를 세는 것과 '무엇을 하라'고 말하는 것은 다른 일이다**: 대시보드는 이미 마감·회신
  기한 초과·미확인 근거 변경을 다 세고 있었지만 칩으로 흩어져 있어 '무엇부터 손대나'가
  안 보였다. `_blocked_rows()` 는 **새로 세지 않는다** — `compute_metrics` 의 결과를 모아
  할 일 문장과 갈 탭(`tab`)을 붙일 뿐이다. 세는 곳이 둘이 되면 반드시 어긋난다.

## 근거·진술 신호

- **`source_changed`는 '확인함'으로만 내린다**: 근거 항목을 수정한다고 꺼지지 않는다
  (`POST /evidence/{eid}/acknowledge`). 자료 원문을 다시 보는 것은 사람의 판단이므로
  위치 오타를 고치는 것과 같은 행위로 취급하지 않는다. 원칙 1·2의 직접적 귀결.
- **프로그램이 센 사실도 '진술' 자리에 둔다**: 보고전 뽑기가 진행상황(단계·진행률·마감·
  미해결 건수)을 근거로 담는다. 지어낸 것은 하나도 없지만 **문서로 확인된 자료도 아니다.**
  그래서 `STATEMENT_KIND` 자료로 만들어 `evidence_mark()` 가 `[진술]` 을 달게 한다 —
  확정 문서로 위장시키면 최종본 점검이 무의미해진다.
  바로 `사용자 확정`을 붙이는 것은 담당자 진술의 채택과 같다: **상자를 켜고 ‘뽑기’를 누른
  행위가 곧 채택**이다. 여기서 확정을 한 번 더 요구하면 '빠른 길'의 명분이 사라진다.
- **`resources.note` 는 `changed` 계산에서 뺀다**: 메모는 자료의 내용이 아니라 그 자료를
  어떻게 볼지에 대한 사람의 말이다. 메모 한 줄에 확정이 풀리고 근거마다 신호가 뜨면
  아무도 메모를 안 쓴다. 같은 이유로 메모는 AI 분석에도 넘기지 않는다 —
  사람의 말이 자료의 사실인 것처럼 요약에 섞이면 `[진술]`/`[확정]` 구분이 흐려진다.

## 목차 파괴 방지·되돌리기

- **보고전은 계획서를 덮어쓰지 않는다 — 새 업무로 뽑는다**: v0.19에 보고전 틀을 넣으면서
  같은 업무의 목차를 갈아끼우게 만들었다가, 진행 중이던 '폐교 활용'(공모사업 계획서)의
  목차 19개·집필카드 19개·본문·검토의견이 사라지고 근거의 목차 연결이 끊기는 사고가 났다.
  **보고전은 계획서의 한 부분이 아니라 다른 문서다.** `POST /projects/{pid}/spinoff` 가
  새 업무를 만들고 **확정 근거만** 가져온다(같은 `resource_id`를 가리키므로 자료가 바뀌면
  양쪽에 `source_changed` 신호가 뜬다 — 복사가 아니다). 프런트는 고른 틀의 계열이 지금
  업무와 다르면(`crossFamily`) 덮어쓰기 버튼을 숨기고 뽑기를 내민다.
  덮어쓰기는 `<details>` 안에 접어 두되 없애지는 않았다(의도적 전환은 가능해야 하므로).
- **파괴적 동작의 확인 문구는 사라지는 것을 전부 세어 말한다**: 위 사고의 원인 하나는
  확인 문구가 "집필카드와 본문"만 말하고 **검토의견·근거 연결을 말하지 않은 것**이었다.
  `GET /outline/replace-preview` 가 목차·카드·본문·검토의견·근거연결·자료요청연결을 센다.
  새로 파괴적 동작을 만들 때는 미리보기 엔드포인트를 함께 만든다(`delete-preview` 와 같은 꼴).
- **`put_outline`은 사라진 목차의 검토의견도 정리한다**: 예전엔 카드·본문·근거·자료요청만
  다루고 `review_opinions`를 빠뜨려, 죽은 목차를 가리킨 의견이 검토 목록에 계속 떴다.
  '지워진 목차의 유령 본문'과 같은 종류의 사고다. 목차에 매달리는 테이블을 새로 만들면
  반드시 이 함수에 정리 규칙을 추가할 것.
- **되돌리기는 파괴적 버튼 옆에 둔다**: v0.19에 목차 19개를 잃고도 확인 문구만 고쳤다.
  사람은 확인 문구를 읽고도 누른다. `put_outline` 이 **사라지는 항목이 있을 때만** 스냅샷을
  찍는다(이름 고치기·순서 바꾸기는 잃을 것이 없다 — 매번 찍으면 정작 필요한 것이 밀려난다).
  되돌리기 자체도 직전 상태를 찍는다 — **되돌리기가 새로운 사고가 되면 안 된다.**
- **되돌리기가 또 다른 파괴가 되지 않게 한다**: 목차·카드·본문은 그때로 되돌리되,
  검토의견은 **사라진 것만** 되살리고(그 뒤 새로 생긴 것은 그대로), 근거·자료요청은
  **끊긴 연결만** 다시 잇는다(사람이 그 뒤에 이어 둔 것을 덮지 않는다). `services/snapshot.py`.
- **백업은 마이그레이션보다 먼저**: `db.backup_db()` 를 `init_db()` **앞에서** 부른다.
  새 버전이 DB 를 잘못 건드렸을 때 손대기 전 파일이 남아 있어야 한다. 하루 한 개인 이유는
  아침에 켠 뒤 오후에 사고가 나면 **그날 첫 상태**가 필요하기 때문이다.
  실패해도 앱은 그대로 뜬다(백업 때문에 프로그램이 안 켜지면 더 나쁘다).

## 문서·파일 읽기

- **확장자를 믿지 말 것 — 시그니처도 겹친다**: `.hwp`·`.xls`·`.doc` 는 **모두 같은 OLE
  복합문서 시그니처**(`D0CF11E0…`)로 시작한다. 이걸 그냥 hwp 로 보내면 구형 엑셀을 올린
  담당자에게 "한글 파일에서 글자를 찾지 못했습니다"라는 엉뚱한 말이 나간다.
  `_cfb_kind()` 가 안에 든 스트림 이름(`Workbook`/`WordDocument`)으로 갈라
  **왜 못 읽는지와 어떻게 하면 되는지**를 말해 준다. 압축(`PK`)도 마찬가지로
  hwpx·xlsx·docx 가 겹치므로 `_zip_kind()` 가 내부 경로로 가른다.
- **행정 시스템의 '엑셀 내려받기'는 흔히 엑셀이 아니다**: 실물 `.xls` 하나를 열어 보니
  내용이 **HTML 표**였다(2026-08-29). 도서관·행정정보 시스템이 그렇게 내보낸다.
  확장자만 보고 "구형 엑셀이니 .xlsx 로 저장하세요"라고 안내하면 담당자는 엉뚱한 길로 간다
  (한글에서 다시 저장할 방법이 없다). `_looks_html()` 이 내용으로 알아보고
  `read_html_table()` 이 같은 격자로 읽는다 — 표라는 점은 같기 때문이다.
  `<style>`/`<script>` 안은 글이 아니므로 건너뛴다(안 그러면 CSS 가 본문에 섞인다).
- **엑셀은 격자로 읽는다 — 문단으로 풀면 수치가 죽는다**: 부서 회신 엑셀은 대개
  '항목 × 연도' 표다. 칸을 뭉개면 `2,431` 이 어느 해 것인지 사라져 AI 도 사람도 못 쓴다.
  병합셀은 hwpx 와 **같은 규칙**으로 덮인 칸마다 원래 글자를 채운다(행 하나가 스스로 완결).
  다만 본문으로 펼 때(`to_text`) **한 줄이 전부 같은 글자면 가로 병합된 안내줄**이므로
  한 번만 적는다 — 안 그러면 `자료: 주민등록 인구통계` 가 칸 수만큼 반복된다.
  날짜·정수 서식도 되돌린다(`2431.0`·`2024-01-01 00:00:00` 로는 원본과 대조가 안 된다).
- **엑셀에서 통째로 빈 열은 버린다**: A·B 를 비우고 C 부터 쓰는 시트가 흔하다.
  그대로 두면 모든 줄이 ` │  │ 124` 로 시작한다(`_drop_empty_cols`).
  다만 **가로 병합으로 같은 값이 반복되는 것은 그대로 둔다** — 붙어 있는 같은 값을
  묶어 버리면 `0 │ 0 │ 0` 같은 진짜 수치가 사라진다. 한 줄이 통째로 같은 값일 때만 접는다.
- **파일에서 읽어 온 본문을 편집 칸에 두지 말 것**: 엑셀 한 장이 수천 자라 화면을 다 차지하고,
  무엇보다 **한 글자만 건드려도** `update_resource` 의 `changed` 가 켜져 확정이 풀리고
  그 자료를 쓰는 근거마다 `source_changed` 가 뜬다. 파일 자료는 접어서 읽기만 하고
  (`ResourceRoom` 의 `showText`), 사람이 쓸 자리로 **담당자 메모**(`resources.note`)를 둔다.

## 가이드라인

- **짝짓기 결과를 확신에 차서 적지 말 것**: 배점 ↔ 목차는 이름 유사도로 맞춘다(threshold 0.34).
  그 결과를 집필카드에 문장으로 박으면 초고까지 그대로 가므로, **확신이 낮으면 낮다고 적는다**
  (`score_note`). 틀린 배점을 단정해 적어 두면 담당자가 엉뚱한 항목에 분량을 쏟는다.
  `purpose` 는 **덮어쓰지 않고 이어 붙인다** — 앞 문장도 사람이 쓸 재료다.
- **정정 공고 비교는 자동으로 고치지 않는다**: 무엇이 달라졌는지만 짚고, 이미 심어 둔
  목차·자료요청은 건드리지 않는다. 목차를 자동으로 갈아끼우면 v0.19 사고를 다른 문으로
  되풀이하는 것이다(그 자리엔 `confirmReplace` 도, 스냅샷도 걸리지 않는다).
  **다시 읽지 않고 저장된 분석끼리 견준다** — 분석은 이미 사람이 범위를 골라 확인한 것이므로
  여기서 추측을 더 보태지 않는다.

## 화면(프런트)

- **화면에서 여는 문서·파일은 `frontend/public/` 에 둔다**: 사용설명서를 백엔드 라우트
  (`GET /사용설명서`)로 냈더니 **개발 서버(5173)에서 빈 화면**이 떴다. vite proxy 는 `/api` 만
  8000 으로 넘기고 나머지는 SPA 로 되돌리기 때문이다. `frontend/public/` 에 두면 vite 가
  개발 중에 그대로 서빙하고 빌드 때 `dist` 로 복사하므로, 개발과 포터블이 같은 주소로 열린다.
  한글 파일명은 퍼센트 인코딩으로도 정상 서빙됨을 확인했다.
- **`.rowbtns` 안에 `select`와 `input`을 섞지 말 것 — 이제 안 섞어도 된다**: 예전 규칙이
  `.rowbtns .btn{flex:1}` + `.rowbtns input{flex:1}` 이라 `select`에는 flex가 안 걸렸다.
  `.cf select{width:100%}` 와 만나 select가 폭 전부를 차지하고 **input이 폭 0으로 밀려**
  집필카드의 '예상 분량'을 아예 입력할 수 없었다. 화면상 칸이 없으니 원인을 찾기 어렵다.
  이제 `.rowbtns>*{flex:1 1 0;min-width:0}` 으로 자식 종류와 무관하게 균등 분배한다.
  **flex 컨테이너에 규칙을 걸 때는 태그별이 아니라 `> *` 로 건다.**
- **스크롤 통을 '칸 전체'로 두지 말 것 — 머리는 고정, 몸만 스크롤**: `.col{overflow:auto}` 라
  도구 막대(항목 추가·이동·삭제)가 목차와 같은 통에 들어 있어 함께 떠내려갔다. 목차가 스무 개만
  넘어도 "항목을 고르고 → 위로 올라가 버튼을 찾고 → 다시 내려와 확인"하는 왕복이 생긴다.
  `.col.pane`(overflow:hidden + flex) + `.pane-head`(고정) + `.pane-body`(overflow:auto)로 나눈다.
  **선택 상태에 반응하는 버튼은 언제나 선택한 것과 함께 보여야 한다.**
- **되돌릴 수 없는 버튼 위에서는 드롭다운을 쓰지 말 것**: 목차 틀 고르기가 `<select>`였는데,
  그 안에 접혀 있던 것은 유형 여덟 개가 아니라 **계열(계획서/보고전)** 이었다. 계열은 초고 문체와
  '진행 중인 업무에 덮어쓸 수 있는가'(`crossFamily`)를 가르는데, 바로 옆 버튼이 되돌릴 수 없는
  '새로 채우기'다. 계열은 탭(`.famtabs`), 유형은 카드 목록(`.tplcard`), 고른 틀의 최상위 항목은
  미리보기(`.tpl-peek`)로 편다. 계열 탭은 **별도 상태를 두지 않는다** — 고른 유형이 곧 계열이다
  (`pickFamily`가 그 계열의 첫 유형을 고른다). 두 상태를 두면 어긋날 자리가 생긴다.
- **`obj.length` 는 대괄호로 읽는다**: 집필카드의 분량 칸 키가 하필 `length`다.
  `card.length` 는 배열 길이처럼 읽혀 리뷰에서 놓치기 쉬우므로 `card["length"]` 로 쓴다.
- **오류 표시**: `api.js`의 `req()`는 FastAPI의 `detail`이 문자열/배열/객체 어느
  것이어도 사람이 읽을 문자열로 변환한다. 유지할 것.

## 데이터·용어 설계

- **부분 업데이트**: 업무 저장 시 보낸 필드만 갱신. 예전에 이름만 바꿔도 목적·대상·
  마감이 지워지던 버그가 있었다. (projects.py는 이제 부분수정)
- **`projects.status`·`stage`는 죽은 컬럼이다**: 스키마에 있지만 어디서도 읽지 않는다
  (대시보드의 단계는 `compute_metrics`가 매번 계산한다). 보관함을 만들 때 이 컬럼을
  재활용하지 않고 `archived_at`을 새로 둔 이유다 — 의미가 겹치면 나중에 반드시 헷갈린다.
- **업무 상태는 '보관'이지 '보류'가 아니다**: 이 앱에는 이미 `보류`가 세 군데 있다 —
  자료요청 상태, 검토의견 처리 상태, 근거의 `사용 보류`, 그리고 진행상황 보고의
  `status_label`. 업무 캐비넷까지 `보류`로 부르면 같은 단어가 네 뜻이 된다.
  그래서 사용자와 상의해 **보관/보관함**으로 정했다. 코드·컬럼·API는 `archived` 로 통일.
- **메모 칸은 하나, 문만 여럿으로 둔다**: 회신 파일을 붙이면서 '회신에 대해 남길 말' 자리를
  자료요청 화면에 따로 만들었더니, 같은 뜻의 칸이 셋이 되었다(`data_requests.note`(비고),
  `received_note`, `resources.note`). 사용자가 바로 "회신 메모는 뭐하는 기능이냐"고 물었다.
  → `received_note` 는 **등록 전** 짧은 회신을 글자로 받는 입구라는 원래 일만 하고,
  **등록 뒤에는 그 자료의 `resources.note` 를 그 자리에 띄운다**(`PUT /resources/{rid}/note`).
  저장되는 곳은 한 군데다. '보류'가 네 뜻이 될 뻔한 것을 보관/보관함으로 갈랐던 것과 같은 판단.
  전용 엔드포인트를 둔 이유: `PUT /resources/{rid}` 는 본문까지 통째로 받으므로
  메모 한 줄을 고치려고 부르면 이름·본문이 빈 값으로 덮인다.
- **없는 id 를 가리키는 열은 '등록됨'이 아니다**: `data_requests.received_resource_id` 에는
  FK 가 없어서 회신자료를 지우면 없는 id 가 그대로 남았다. 화면은 `등록됨: (삭제된 자료)` 라고만
  하고 **다시 등록할 길도, 메모를 남길 길도 막혔다**(v0.21에 사용자가 발견).
  읽는 쪽(`_row`)에서 없는 것은 `None` 으로 돌려주고 `received_lost` 로 사실만 알린다.
  **가리키는 대상이 사라질 수 있는 열을 만들 때는 읽는 쪽에서 반드시 확인할 것.**
- **목록을 `SELECT *` 로 읽는 표에 BLOB 컬럼을 넣지 말 것**: 원본 파일을 `resources` 에
  넣었다면 자료 목록을 부를 때마다 수십 MB 가 프런트로 나갔을 것이다. 딴 표
  (`resource_files`)에 두고 목록에 실을 컬럼은 `file_meta()` 가 못박는다.

## 서식·AI 설정

- **서식도 `family_of` 로 갈린다**: 보고전을 계획서 서식으로 내보내면 표지와 번호가 붙어
  한 쪽짜리라는 값어치가 사라진다. `export_docx` 가 계열로 갈라 `_brief_docx()` 를 쓴다.
  **줄머리(○·-)는 사람이 쓴 것을 그대로 쓴다** — 깊이로 다시 만들어 붙였더니 ○ 로 쓴 줄이
  - 로 바뀌어 나왔다. 깊이는 들여쓰기에만 쓴다(본문을 고쳐 쓰지 않는다는 원칙이 서식에도 적용).
  하위 항목을 거느린 묶음('본문'·'결론')에는 '(본문 없음)'을 찍지 않는다.
- **AI 키는 화면 값이 `.env` 를 이긴다**: `.env` 는 시작할 때 한 번 읽으므로 고치면 재시작이
  필요했다. `services/aiconfig.py` 가 `settings` 의 `ai.*` → `.env` 순으로 읽어 **저장 즉시**
  반영한다. `.env` 를 없애지 않은 이유는 관리자가 키를 미리 넣어 반입할 수 있어야 하기 때문.
  화면에는 **어느 쪽에서 온 값인지**를 표시한다 — 안 그러면 "분명히 넣었는데 왜 안 되지"가 된다.
- **키 입력칸에서 빈 칸은 '그대로 두기'다**: 키는 화면에 다시 보여주지 않으므로(끝 4자리만),
  빈 칸으로 저장을 누르는 것이 '지우기'라면 실수로 키가 날아간다. 지우기는 별도 버튼에서
  명시적으로 `""` 를 보낸다. **연결 시험을 반드시 함께 둔다** — 키가 틀린 것과 망이 막힌 것은
  담당자가 해야 할 일이 전혀 다른데, 시험이 없으면 둘을 구분할 방법이 없다.

## 문서·파일 읽기(XML)

- **XML 은 전부 `defusedxml` 로 파싱한다**(2026-10-01). 공공GitLab 의 pre-receive 보안
  스캔(Semgrep)이 표준 `xml.etree` 사용을 ERROR 로 막아 push 가 거부됐다. 지적이 타당했다 —
  hwpx·docx 는 ZIP+XML 이고 그 파일은 부서 회신처럼 **남이 준 것**이라 XXE·XML 폭탄의
  입구다. 바꾼 뒤 외부 엔티티가 실제로 `EntitiesForbidden` 으로 막히는 것을 확인했다.
  `defusedxml` 은 **읽기만** 안전하게 해 준다(fromstring·iterparse·parse·tostring).
  쓰는 쪽은 없으므로 `SubElement` 는 `_subelement()`(makeelement+append)로 직접 두고,
  `ElementTree(fromstring(x))` 는 `parse(BytesIO(x))` 로 바꾼다.
- **hwpx 의 네임스페이스 접두사는 유지하지 않아도 된다**(같은 날). `register_namespace` 로
  원본 접두사(`hp:`·`hs:`)를 살려 저장해 왔는데, 그 한 줄 때문에 표준 `xml.etree` import 가
  남아 스캔을 통과하지 못했다. 접두사를 등록하지 않고 저장한 파일(`ns0:`·`ns1:`)을
  **한글에서 열어 확인했더니 정상으로 열렸다.** 접두사는 XML 에서 의미를 갖지 않으므로
  표준대로 동작한 것이다. 그래서 등록을 걷어냈다.
  → 이때 **시험을 같은 프로세스에서 하면 속는다**: `register_namespace` 는 모듈 전역
  레지스트리를 영구히 바꾸므로, 등록하는 쪽을 먼저 돌리면 등록을 건너뛴 쪽도 접두사가
  살아 있는 것처럼 보인다. 실제로 그렇게 한 번 잘못 읽었다 — 별도 프로세스에서 다시 쟀다.
- **의존성 하한은 '실제로 돌려 본 버전'으로 적는다**(같은 날). OSV-Scanner 가 걸린 것은
  설치본이 아니라 `requirements.txt` 의 **하한**이었다(`pypdf>=4.0` → PYSEC 55건).
  설치된 것은 훨씬 최신이어서 `pip-audit` 은 "No known vulnerabilities" 였다.
  직접 import 하지 않는 간접 의존성(`anyio`·`idna`·`starlette`·`certifi`·`httpcore`)도
  하한을 적어 둔다 — 적지 않으면 스캐너가 '허용되는 가장 낮은 버전'을 골라 검사한다.
- `nosemgrep` 주석은 **믿을 수 없다**. 서버 스캐너가 억제를 무시하도록 돌릴 수 있다
  (실제로 무시됐다). 규칙에 걸리는 코드는 억제하지 말고 없애거나, 담당자와 협의한다.

## 코드 습관·테스트

- **라우트 데코레이터 위치 주의**: 집계 로직을 함수로 뺄 때 `@router.get("/dashboard")`
  가 실수로 `compute_metrics(c,p)` 위에 붙어, FastAPI가 c·p를 쿼리 파라미터로
  요구해 422 → 프런트에 "[object Object]"로 표시된 사고가 있었다. 데코레이터는
  **엔드포인트 함수에만**.
- **테스트 방식**: TestClient는 컨텍스트매니저로 쓰지 않으므로 lifespan이 안 돈다 →
  테스트에서 `init_db()`를 명시 호출. LLM은 fake provider로 주입해 검증.
- **설정을 건드리는 테스트는 임시 DB로 돌린다**(2026-10-01, 호환 서버 작업 중).
  `ai.*` 설정을 바꿔 보는 시험을 실제 `workbench.db` 로 돌렸다. 중간 단언이 실패하며 죽자
  시험용 값(`COMPAT_BASE_URL`, 빠름 등급 = compat)이 DB에 남았고, 다음 실행이 **그 남은 값을
  '원래 값'으로 기억해** 되돌렸다. 오염이 굳은 것이다. 되돌리기를 `finally` 로 감싸는 것으로는
  모자랐다 — 원본을 어디서 읽는지가 문제였다.
  고친 방법: `app.db` 를 import 한 뒤 `db.DB_PATH`·`db.BACKUP_DIR` 를 임시 폴더로 갈아끼운다.
  `connect()` 가 부를 때마다 모듈 전역을 읽으므로 이것으로 충분하고, 되돌릴 것이 아예 없어진다.
- **환경변수를 치우는 것은 `app.main` import 뒤에**(같은 작업). '키가 없을 때'를 시험하려고
  `os.environ.pop()` 을 먼저 했는데, `app.main` 이 `.env` 를 로드하면서 되살아났다. 그 바람에
  '키가 없습니다'를 기대한 자리에서 **실제 OpenAI 를 호출**해 모델 목록을 받아 왔다.
