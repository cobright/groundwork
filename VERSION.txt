- AI는 쪼개기만 합니다. 없는 사실을 채우지도, 요약하지도, 평가하지도 않습니다.
  AI를 못 쓰는 상황에서도 줄 단위로 쪼개져 그대로 쓸 수 있습니다.
- 진술은 '문서로 확인된 자료'와 끝까지 구분됩니다. 초고·검토·최종본 부록에
  [진술]로 표시되고, 최종 점검에서 "대외 제출 문서라면 문서 근거가 필요한지
  확인하세요"라고 알려 줍니다. 막지는 않습니다.

[ 새 기능 ] 보고전 뽑기
- 계획서를 쓰던 중 상부 보고가 필요할 때, 그 업무에서 보고전을 '새 업무'로 뽑습니다.
  진행 중인 계획서는 손대지 않습니다.
- 확정된 근거가 함께 넘어갑니다. 복사가 아니라 같은 자료를 가리키므로,
  자료를 고치면 양쪽 모두에 '자료 변경됨' 신호가 뜹니다.

[ 새 기능 ] 사용설명서
- 맨 위 '사용설명서' 버튼을 누르면 새 창에서 열립니다. 프로그램 폴더 맨 위에도
  '사용설명서.html' 로 들어 있어, 두 번 눌러 열거나 인쇄해서 보실 수 있습니다.
- 업무 등록부터 한글 문서 내보내기, 보고전 작성, 막힐 때까지 12장입니다.

[ 바로잡은 것 ]
- 계획서 업무에서 보고전 틀을 넣으면 그 업무의 목차·집필카드·본문이 사라지고
  근거·검토의 목차 연결이 끊겼습니다. 이제 계열이 다르면 덮어쓰지 않고
  새 업무로 뽑습니다. (그래도 바꾸려면 접힌 항목을 펴서 할 수 있습니다)
- 목차를 통째로 바꿀 때의 확인 문구가 '집필카드와 본문'만 말했습니다.
  이제 사라지는 것을 전부 셉니다 — 목차·집필카드·본문·검토의견·근거 연결·자료요청 연결.
- 목차를 지워도 그 목차의 검토의견이 남아, 없는 목차를 가리킨 채 검토 목록에
  계속 떴습니다. 이제 함께 정리합니다.
- 없는 기능을 부르면 "Method Not Allowed"라는 알 수 없는 말이 떴습니다.
  이제 "프로그램을 껐다가 다시 켜 주세요"라고 실행 중인 버전과 함께 알려 줍니다.
- 집필카드의 '예상 분량'에 아무것도 입력할 수 없었습니다. 옆의 '작성 상태' 선택칸이
  자리를 다 차지해 입력칸이 폭 0으로 밀려 있었습니다. 두 칸을 나란히 놓았습니다.
- 집필카드 입력칸이 전부 비어 있어 무엇을 적어야 할지 알 수 없었습니다.
  칸마다 예시 안내가 붙고, 맨 위에 "여기 적은 것이 그대로 초고의 재료가 됩니다"라고
  적었습니다. (보고전 틀은 지금까지처럼 카드가 미리 채워집니다)

* 프로그램을 새로 받으신 뒤에는 반드시 껐다가 다시 켜 주세요.
  켜져 있는 동안에는 예전 기능으로 돌아갑니다.
* DB는 자동으로 갱신되며, 기존 업무·자료·근거는 그대로입니다.

v0.18 — 보관함(캐비넷) 신설 + 코드 전면 점검 반영

[ 새 기능 ] 업무 보관함
- 지워야 할지는 모르겠지만 지금 관리 대상은 아닌 업무를 넣어두는 곳입니다.
  대시보드 업무 카드의 '보관'를 누르고, 원하면 사유를 한 줄 적습니다.
  (예: 공모 탈락, 내년 재검토 / ○○부서 협의 대기)
- 보관한 업무는 상황판·업무 선택 목록·집계에서 빠지지만 지워지지 않습니다.
  상황판 맨 아래 '보관함'에서 언제든 되살릴 수 있습니다.
- 업무 삭제는 이제 '보관함 안에서만' 가능합니다. 진행 중인 업무는 삭제되지 않습니다.
  삭제할 때는 무엇이 사라지는지(목차·본문·자료·근거·검토의견 건수)를 보여주고,
  업무명을 그대로 입력해야 진행됩니다. 삭제는 되돌릴 수 없습니다.
  · 공통자료실 자료는 업무를 지워도 남습니다(참조만 끊깁니다).

[ 바로잡은 것 ]
- 근거 번호(E-번호)가 화면마다 달랐습니다. 근거표는 전체 순번, 초고·검토는 목차별
  순번을 써서, AI가 본문에 단 '(근거: E-003)'이 근거표의 다른 항목을 가리켰습니다.
  이제 업무 전체에 하나의 번호만 쓰며, 최종본 .docx 부록 근거표에도 번호 열이 생겨
  본문에서 부록으로 바로 찾아갈 수 있습니다.
- '근거 자료 변경됨' 표시가 근거를 조금만 고쳐도 조용히 꺼졌습니다. 이제 자료 원문을
  다시 확인하고 '확인함'을 눌러야만 내려갑니다.
- 목차를 지워도 그 목차의 본문이 DB에 남아 진행률에 계속 잡혔습니다(목차 1개인데
  본문 3개로 세어 '마무리 단계'로 보이는 식). 대시보드와 진행상황 보고가 함께
  틀리던 문제입니다. 이제 지운 목차의 집필카드·본문을 함께 정리합니다.
  (근거·자료요청은 지우지 않고 목차 연결만 끊습니다)
- 목차를 고친 직후 업무명을 건드리면 목차 저장이 취소되어 편집이 사라질 수 있었습니다.
- 자료요청서 xlsx의 '요청일' 열 이름이 잘못 붙어 있었습니다.
- 부서명에 / \ ? * [ ] 가 들어가면 xlsx 내보내기가 실패하던 문제.
- 최종본 .docx의 제목 줄에 한글 글꼴(맑은 고딕)이 적용되지 않던 문제.
- 문서 전체 검토에서 문서가 너무 길면 앞부분만 검토하고 그 사실을 알립니다.

[ 설치·배포 ]
- 1_SETUP.bat 이 설치 후 패키지가 실제로 불러와지는지 확인하고, 어긋난 가상환경은
  지우고 다시 만듭니다. 파이썬은 3.12/3.11을 우선합니다.
  (이전 버전에서 파이썬 버전이 섞여 서버가 아예 켜지지 않는 일이 있었습니다)
- 포터블 꾸러미를 만들 때 개발 PC의 .env(실제 API 키)가 딸려 들어가지 않도록
  제외합니다. 꾸러미에는 빈 키 템플릿만 들어갑니다.
- 실행용 백엔드에서 개발용 --reload 옵션을 뺐습니다.

* DB는 자동으로 갱신되며(보관 관련 항목 추가), 기존 업무·자료·근거는 그대로입니다.

v0.17 — 포터블 배포(설치 없이 행정망 실행) 준비
- 목표: 행정망처럼 설치가 어려운 PC에서 '설치 없이' 실행.
  인터넷 PC에서 포터블 폴더를 한 번 만들고 → 행정망으로 폴더 반입 →
  '실행.bat' 더블클릭으로 구동(파이썬을 시스템에 설치하지 않음).
- 코드 포터블화:
  · 모든 경로가 파일 위치(__file__) 기준 → 폴더째 옮겨도 동작
  · .env 를 backend 폴더 기준으로 로드(작업 위치 무관)
  · uvicorn[standard] → uvicorn(+h11)로 변경: 컴파일 확장 최소화(임베디드 파이썬 친화)
  · backend/run.py 추가: 더블클릭/임의 위치에서도 서버 기동 + 브라우저 자동 열기
- 폴더 선택창 강화: tkinter 가 없는 임베디드 파이썬에서도 작동하도록
  윈도우 PowerShell 폴더 대화상자로 자동 폴백(둘 다 안되면 직접 입력 안내)
- portable\ 폴더 제공:
  · 포터블_만들기.bat : 인터넷 PC에서 한 번 실행(파이썬 임베디드+패키지 담기)
  · _build_portable.ps1 : 실제 조립 스크립트(파이썬 3.11 임베디드 기준)
  · 실행.bat : 포터블 폴더 안에서 워크벤치를 켜는 런처
  · 사용설명.txt : 1)만들기 → 2)반입 → 3)실행 안내
- 이 압축에는 미리 빌드된 frontend\dist 가 포함되어 행정망에 Node 가 필요 없습니다.

주의(정직한 한계):
  · 포터블 '조립'은 윈도우에서 실행됩니다. 리눅스에서 만든 개발자 환경에서는
    최종 조립을 대신 만들 수 없어, 인터넷 되는 윈도우 PC에서 1회 실행이 필요합니다.

    (나머지 기능은 정상). 인터넷이 되더라도 방화벽이 해당 도메인을 막는 경우가
    있으니, 안 되면 망 정책을 먼저 확인하세요.
