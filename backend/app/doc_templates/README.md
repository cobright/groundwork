# 문서 유형(목차 틀) 파일

그라운드워크의 '문서 유형별 목차 생성'에 나오는 틀은 모두 이 폴더의 파일에서 옵니다.
**파일 하나가 문서 유형 하나**입니다. 코드를 몰라도 파일을 고치거나 더해 새 유형을 보탤 수 있습니다.
고친 뒤에는 프로그램을 껐다 켜야 반영됩니다.

## 파일 모양

```json
{
  "유형": "공모사업 계획서",
  "계열": "계획서",
  "순서": 10,
  "목차": [
    {
      "항목": "추진배경",
      "작성 목적": "심사위원이 첫 장에서 ‘왜 지금 이 사업인가’를 납득하게 한다",
      "핵심 질문": "무엇이 이 사업을 지금 하게 만들었는가?",
      "반드시 포함할 내용": "상위계획·법령 근거, 지역의 변화(수치), 공모 취지와의 연결",
      "분량": "0.5~1쪽"
    },
    {
      "항목": "과업 범위",
      "하위": ["기본 과업", "선택 과업"]
    },
    "과업 수행방법"
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `유형` | 화면에 보이는 문서 유형 이름. 다른 파일과 겹치면 안 됩니다. |
| `계열` | `계획서`(여러 쪽, 문단으로 씀) 또는 `보고전`(한 쪽, 개조식). **초고의 문체와 내보내기 서식이 이것으로 갈립니다.** |
| `순서` | 화면에 늘어서는 순서(작은 수가 먼저). |
| `목차` | 항목 목록. 항목은 이름만 적은 글자(`"과업 수행방법"`)이거나, 아래 칸을 가진 묶음입니다. |

항목 묶음에 쓸 수 있는 칸 — 화면의 **집필카드** 칸 이름과 같습니다:

| 칸 | 뜻 |
|---|---|
| `항목` | 목차 항목 이름(필수) |
| `하위` | 아래 항목 목록 |
| `작성 목적` | 이 항목을 왜 쓰는가 |
| `핵심 질문` | 이 항목이 답해야 할 질문 하나 |
| `핵심 메시지` | 이것만 기억된다면 무엇이어야 하는가 |
| `반드시 포함할 내용` | 빠지면 안 되는 것 |
| `분량` | 예: `1쪽`, `0.5쪽`, `2~3줄`. 비우면 `1쪽` |

집필카드 칸이 하나도 없는 항목은 '카드 없음'으로 나옵니다. 칸 이름을 잘못 쓰면(예: `작성목적`)
프로그램이 뜰 때 **어느 파일의 어느 항목이 틀렸는지** 알려 줍니다.

`_` 로 시작하는 파일(`_목차안_조합.json`)은 유형이 아니라, 계획서 계열에서 쓰는 '목차안 조합' 블록입니다.

## 새 유형을 보탤 때 — 가장 중요한 것

**집필카드 안내는 실제로 그 문서를 써 본 경험에서 나와야 합니다.** 짐작으로 채운 안내문은
없느니만 못합니다(엉뚱한 것을 '반드시 포함할 내용'이라고 믿게 만듭니다). 확신이 없는 항목은
카드 칸을 비워 두세요 — 지금 있는 유형 중에도 카드가 빈 것이 여럿 있습니다(`용역 과업지시서` 등).
PR 을 보내실 때는 어떤 경험(심사표, 반려 사유, 실제 양식)에서 나온 안내인지 짧게 적어 주세요.

- 보고전 4종은 청와대 비서실 보고서 작성법의 표준 서식에서 구조를 그대로 읽어 왔습니다.
- 공모사업 계획서의 카드는 공모 심사에서 실제로 배점이 붙는 자리(근거·수치·출처·지속성)에서 가져왔습니다.

파일을 고친 뒤 `cd backend && python -m pytest tests/test_templates.py` 로 확인할 수 있습니다.
